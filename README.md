# Temporal Literature Investigator

Exploring History Through Literature — a RAG system that connects the **novels in a
book-review corpus** to the **historical events of their era**, in both directions
("what shaped this novel?" / "which novels came out of this moment?").

The book corpus is the Persian-language blog **سفر در کتاب‌ها** (Travel in Books),
parsed from `../travel-in-books.github.io/_posts/`. Each review already carries the
key join keys: **publication year + country**. The missing half — a historical
timeline per (country, decade) — is generated by Claude and cached locally.

## Architecture

```
_posts/*.md ──► ingest ──► data/books.jsonl ──┐
                                              ├─► index ─► Chroma vector store ─► ask ─► Claude (Opus 4.8)
(country,decade) ─► build-history ─► data/history/*.json ─┘
```

- **LLM backend**: `cli` (default) drives the authenticated **`claude -p`** command —
  **no API key needed**. Switch to `sdk` (anthropic SDK + `ANTHROPIC_API_KEY`) via
  `TLI_LLM_BACKEND` for token streaming / lower latency.
- **Embeddings**: multilingual (Persian-capable). Default backend `local`
  (`intfloat/multilingual-e5-large`, offline, no key); optional `voyage`.
- **History layer**: generated with Claude Haiku 4.5 (cheap, bulk), cached to
  `data/history/`.
- **Synthesis**: Claude Opus 4.8, bilingual, cites the book reviews it used
  (token-streamed on the `sdk` backend).

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .                 # or: pip install -r requirements.txt
cp .env.example .env             # defaults to the no-key `claude -p` backend
```

By default the app calls your local `claude` CLI, so no API key is required. To use
the SDK instead, set `TLI_LLM_BACKEND=sdk` and `ANTHROPIC_API_KEY` in `.env`.

**Speed tips (from a real run):**
- For a fast first run, use the smaller embedder:
  `export TLI_LOCAL_EMBED_MODEL=intfloat/multilingual-e5-small` (~470 MB vs 2.2 GB).
  Use the **same** value for `index` and `ask` so query/document vectors match.
- `build-history` makes ~89 sequential calls (one per country×decade in this corpus).
  On the `cli` backend each call cold-boots the `claude` CLI (slow, ~tens of
  minutes total). Results are cached, so it's a one-time cost — but for the bulk
  build the `sdk` backend (with a key) is substantially faster. Interactive `ask`
  is fine on either backend.

## Run the pipeline

```bash
tli ingest                       # parse posts -> data/books.jsonl (normalizes years)
tli build-history                # generate + cache historical timelines (uses Claude)
tli index                        # embed books + events into the vector store
tli info                         # sanity-check corpus / store stats

tli ask "ادبیات روسیه دهه ۱۸۸۰ تحت تأثیر چه رویدادهای تاریخی بود؟"
tli ask "Which novels were written during WWI, and how does the war show up in them?" --from 1914 --to 1918
tli ask "What was happening in Colombia around One Hundred Years of Solitude?" --country کلمبیا
```

`--from/--to` (year range) and `--country` apply a metadata pre-filter before vector
search — essential for temporal queries. `-k` sets how many chunks are retrieved;
`--no-stream` returns the full answer at once.

## Layout

```
src/tli/
  config.py      paths, model IDs, embedding backend (.env-driven)
  utils.py       Persian→ASCII digit + year normalization
  ingest.py      Phase 1: parse posts -> books.jsonl
  history.py     Phase 2: Claude-generated historical events, cached
  embeddings.py  pluggable local / Voyage embedder
  store.py       Chroma collection (cosine, self-supplied vectors)
  index.py       Phase 3: chunk + embed books + events
  rag.py         Phase 4: filtered retrieval + Claude synthesis
  cli.py         `tli` entry point
```

## Notes & next steps

- **Year normalization** is the load-bearing transform (posts mix Persian/Gregorian
  digits) — see `utils.normalize_year`. Books with no detectable year are kept but
  excluded from temporal filtering.
- Prototype chunking is one chunk per book / per event. For production: split long
  reviews by section (characters / themes / chapters) and add a reranker.
- The history layer is LLM-generated for coverage; enrich high-value eras with
  Wikidata later for authoritative citations.
